# 真实视频与原生逐帧复刻

用户要求“逐帧、原配色、百分百复刻”，或指出样片粗糙时，启用这条路线。旧版四秒机制演示不能作为精细复刻验收，也不能把原位淡入改成飞入、把遮罩滑入猜成缩放、把遮光下硬切猜成镜头推近。画风、语法和真实人物画面都按当前对话要求执行。

## 必须实际完成的工作

| 阶段 | 实施 | 证据与验收 |
|---|---|---|
| 完整原片 | 使用已下载原片，核对来源、完整时长、原生尺寸、帧率、帧数、色彩标签和 SHA；不重复下载已验收文件 | 本机完整原片可播放，来源链接、实际视频/音频时长及哈希 |
| 全帧账本 | `scripts/frame_inventory.py` 解码每个原生视频帧，保存真实 PTS、全分辨率 RGB 统计、相邻帧变化和候选切点 | 实际处理帧数、无漏帧/PTS错误；机器处理与 Agent 实看范围分别记录 |
| 完整结构 | 看全时长帧页，区分教程界面与真正效果；一个视频有多个版式时全部列出 | 逐段时间/原生帧号清单，不能只提取第一种手法并称整片已学会 |
| 密集语法分析 | 进入、停留、退出与转场全部连续逐帧查看；测矩形、人物遮罩、图层顺序、字距、运动轨迹和混合方式 | 每帧测量与残差、未知项；遇到新证据纠正旧解释 |
| 原色与字形 | 在解码后的原生 RGB 取样，区分纯填色、渐变、阴影、半透明与压缩差异；记录取样 ROI | 原色样本与输出 ROI 对照；不以整帧平均色/缩略图调色代替配色重建 |
| 真实人物 | 使用实际拍摄视频。需抠像的效果用每帧动态 alpha，保留对应帧的原 RGB 与 PTS | 原片身份、每帧 RGB/alpha/file SHA、边缘检查；一张抠像 PNG 不能替代动态人物 |
| 按帧重建 | 写 measured spec，用 `scripts/reference_render.py` 渲染原生时长、尺寸、帧率与帧号；图层支持逐帧数值/矩阵与动态 RGBA 序列 | 实际 MP4、完整解码、准确帧数、反向 seek 可重现；不统一拉伸成四秒 |
| 对照修复 | 看最终编码连续帧，按源帧对齐；分别评估时间、几何、色彩、遮罩、字体和素材 | 每项 pass/partial/fail/unverified；网页可同步播放/前后逐帧，没有意见输入和记录入口 |
| 迁移新口播 | 换文案/人物后，迁移已验证的规则到真实词轴；保留原视频的 A/V 对和人物反复出镜 | 真实出片审核；研究片段不冒充正式本人数字人口播 |

## “百分百”的判断

- 目标是可核对的细节一致，不能先写“100%已复刻”。原色/时间/轨迹必须依据源帧实测。特征统计不是理解，SIFT 小残差也不证明所有图层一致。
- 相同素材、相同字形和相同构图可以比较像素；换真人与内容后，比较效果层的颜色、遮罩、位置和时间，不能以整帧 SSIM 证明动画一致。真人表演本身会不同。
- 视频未提供字体、无损素材、透明图层、原工程时，原片遮挡区域和具体作者关键帧可能无法唯一恢复。先提取可见静态美术到**私有调研工程**并注明来源；从原片抽取固定字形并不代表已识别字体，也不支持任意新字。
- 原始 B-roll 缺失时，替代照片、修补隐藏纹理、近似光漏和不同人物轮廓都必须列为未一致项。不能用原片成片/动画帧重放冒充可复用效果重建；不能靠修改通过阈值或删掉问题来通过验收。
- H.264/4:2:0 再编码会改变部分 RGB 值。保留原色数据和取样坐标，标注编码色域/范围，比较编码后的实际输出；需要像素级存档时保留无损参考帧。

## 命令与数据

```bash
# 单片原生 PTS 与完整 RGB 遍历；不会下载、转写、远程传输视频
python3 scripts/frame_inventory.py --source /absolute/source.mp4 --out /absolute/frame-audit

# 原生帧重建；spec由Agent根据测量编写，命令不会自动推断逆向图层
python3 scripts/reference_render.py --spec /absolute/measured-spec.json --output /absolute/rebuilt.mp4

# 只读审核页：cases为本地来源/重建文件、原生窗口、测量证据与差异清单
python3 scripts/precision_gallery.py --cases /absolute/cases.json --dir /absolute/review
python3 scripts/serve_review.py --dir /absolute/review --port 58536
```

以脚本的 `--help` 为实际参数来源。`reference_render.py` 当前支持 CFR 原生帧窗口；VFR 会拒绝，不能静默改帧率。必填 `width/height/fps/frames/times/reference/assets/layers`；`reference` 包含完整原片路径、SHA、原生 `first_frame`。每层声明原生帧范围，`x/y/width/height/opacity/blur` 可为逐帧数组或有明确插值方式的 keys；`matrix` 是每帧六值 Canvas 变换。动态序列使用每帧 `paths/times`，需要抠像时 `role:dynamic_foreground`，记录 `source_video/source_sha256/method`，提供真正有 alpha 的动态帧。

判断 CFR 时检查完整原片的实际 PTS，而非只信平均帧率。所有声明 `source_video` 的素材都核对原视频 SHA，并参与输入保护及缓存身份。输出与 manifest 先解析软链接，避免覆盖源片、spec 或引擎。编码前后重复核对全部素材与引擎；中途修改输入时拒绝接受输出。

独立光效可声明 `blend_mode:screen`，记录颜色空间与被遮挡区域的估算方式。文字必须按实际逐字/逐行轨迹重建：外侧向中间翻入不等于从左打字，逐字横向收缩不等于整行淡入。素材同一画面从手机变成大卡时，测量原图的缩放和裁切，不能按面板宽高任意拉伸。可见相同建筑的小幅运动仍要测量；单张 B-roll 加静态数据层不能标为原动态画面已完整复刻。

拟合参数必须回到实际编码帧核验。先拉伸再裁回字格再做横向模糊，与先模糊再把整字放大不是同一种动画；优化分数高但字在原片已清晰而重建仍模糊时，应拒绝该拟合。透明字形变形/模糊用预乘 alpha 运算，避免黑边；提取粗白字不能只留下靠描边的白像素而删掉笔画中心。分别核对各层退出帧，不能把闪光下的标题、说明和字幕统一处理。已确认的实现错误应修复，不能写成“未知字体”或用评估阈值掩盖。

运行成功只确认机械检查，不会自动把 `reference_fidelity` 标成通过。私有原片、静态源美术、模型权重、API 数据与真人素材不打包开源。

完整制作的 `broll-jobs.json` 可使用 `renderer:reference`，提供 measured spec 与输出路径；`produce.py` 会验证原片/所有序列帧的身份、缓存签名和当前输出 hash，再渲染并接入整片。`position:full` 保留该动画原画幅；迁移到新词轴时要另外写对应镜头时间，不能把研究片段原话当正式配音。

## 动态抠像依赖

本机已用 [Robust Video Matting 官方项目](https://github.com/PeterL1n/RobustVideoMatting) 的 MobileNetV3 TorchScript 模型逐帧验证一条真实图库视频：303帧/25fps/12.12秒，每帧 PNG 的 RGB 与原解码字节一致。循环状态按正向顺序推理，不能随机跳帧调用模型。头发/人物随视频运动；耳机等附件有局部半透明误分，需要按实际主体修整，不能说完美。

该模型/项目为 GPL-3.0，未捆绑到本 MIT 包。使用其他分割实现也可，只要输出时间与原 RGB 对齐并完成边缘核验；模型成功不等于所有视频或嘴型质量都通过。无原音/未做口型驱动的图库真人仅用于明确标记的动画演示。
