# 抖音口播参考学习与28个复用模块

来源是2026-10-12抖音搜索「网感口播剪辑」，视频页、全部、默认排序下实际观察到的前30条。登录与推荐影响顺序；不是热度榜，不保证每条是爆款。作者、原片URL、选定时间窗、模块和用途见 [目录](../assets/social-grammars/catalog.json)。完整原片、API响应、转写、抽帧和审核视频留在研究工程，不随技能开源。

## 学习流程

1. 记录浏览器实际搜索顺序、查询词、筛选、时间和作品ID，不用站外搜索凑数。访问受阻就说明，不能假装看过或下载过。
2. 下载完整原片，保存来源、hash、尺寸、时长、实际音视频流。缓存作品ID与详情，防止中断后重复付费请求。HTTP 200不证明拿到视频。
3. 每条查看覆盖全时长的抽帧，再密集查看具体有效窗口。区分软件操作与实际预览。转写帮助理解，但可能有同音错字；抽帧加转写不等于全程实时观看试听。
4. 记录实际布局、动作路径、遮罩、层级、停留与语义目的。静态版式、AI变声、生成式变脸与剪辑运动分别标注，不把教程讲到的功能名当成已看到的动作。
5. 归并机制。第13/29条共享描边开场，第15/25条共享人物后大字。30来源对应28模块，不能称为30种全新独立语法；也不宣称还原整段教程中的全部效果。
6. 替换人物、文字、证据重建代码。交付选定原片片段和实际编码复刻短片，再换长短文字与其他可用素材验证。原片重放不算复用。
7. 当前Codex查看编码帧和密集动作，记录文字、脸部、完整解码、帧数、hash、浏览器错误和倒序seek确定性。网页只展示播放，意见在对话处理。

| 类别 | 典型模块 |
|---|---|
| 人物与证据 | 三段式、上证据下人物窗、双人物窗、群体图标、概念剪影、六格素材 |
| 文字强调 | 逐字块、衬线字层、双色贴纸、推近强调、文字墙、人物后大字、四角字、字碎片、标记条 |
| 构图与转场 | 圆窗弧字、毛玻璃、缩圈、玻璃卡、描边入场、拼贴、矩形蒙版、放射环轨、图表、裂缝、胶片、波浪框、缩略图聚光 |

28模块含人物窗、四角字、六格与胶片等静态版式，不是28种纯运动曲线。旧8种花叔参数语法、新模块、35艺术画风分别处理，不能相乘宣称全部组合已验证。

## 本地渲染

需要Python Playwright、Pillow、FFmpeg与Chromium。媒体、字体在本机，不用CDN。

```bash
python3 <skill>/scripts/social_grammar.py --spec /absolute/shot.json --output /absolute/shot.mp4
```

```json
{
  "grammar":"d02_word_tiles", "duration":4, "fps":24,
  "portrait":"assets/presenter.png",
  "presenter_video":"accepted-master.mp4", "video_start":12.5,
  "title":"重点观点", "detail":"与当前口播句子对应",
  "accent":"#18a16b", "ink":"#ffffff"
}
```

路径相对spec目录。输出1080×1920，支持1–8秒和24/25/30/60fps。`portrait`是授权图像；可选`presenter_video`逐帧seek真实视频。素材短于镜头报错，不冻结末帧填满。镜头输出静音，完整合成保留最终母片原音；不能声称这些样片验证过本人数字人口型。

`cutout`是真实透明人物前景。三段式、描边、人物后字、放射环轨、概念人物、波浪框要求alpha，矩形假抠像被拒绝。当前这些模块支持图像抠像，**尚未实现动态人物分割/alpha视频**，拒绝把静态抠像盖在移动真人上冒充完成。真人需要该效果时，先准备验证过的动态分割，再在项目自定义实现接入alpha帧并逐帧检查。

可选`subtitle`、`items`、`images`、`label`、`values`、`question`、`outline`、`selected`、`direction`。适用关系见目录。没有`images`时使用明确的原创示意图；正式事实证据必须替换真实资料，示意趋势不作业务数据。短词类效果应拆句，不无限缩小长段落。

`title`最多16字，竖排概念/胶片标题最多8字；`detail`最多40字。`items`需1–4个、每项最多12字；双人物窗需要2项，杂志字层/文字墙需要3项，四角字需要4项，玻璃卡片可用1–4项。图表`values`需2–5个0–1数值，九格`selected`为0–8。短词组件仍需逐帧审阅长短适配，输入限制不等于所有长度都审美通过。

## 接入整片

`broll-jobs.json`可选renderer：

```json
[{"renderer":"social","spec":"shots/emphasis.json","out":"broll/emphasis.mp4"}]
```

`shotbook.json`：

```json
{"events":[{"id":"emphasis","component":"broll","start":12.5,"end":16.5,"asset":"broll/emphasis.mp4","position":"full"}]}
```

`produce.py`按spec、引擎、字体和媒体hash缓存。`position:full`只用于视频，直接呈现原先制作的动作，不额外淡入小窗。字幕仍在上方图层，检查重复字幕。使用真人镜头时`video_start`必须与事件时间一致。之后回到原人物，并一起安排开场、观点、结尾的出镜，不把整片做成效果目录。

画风仍由用户在对话指定，语法由Agent按句意安排。「由用户指定」是选择政策，不是一款画风。增加语法无需重渲染全部35款完整片。

## 验证边界

本批工程保存30完整原片、全时长概览、30密集窗口、本地机器转写、30条4秒机制样片、30条复用样片。人物是授权虚构图像或图库人物，横版/教程预览迁移为竖版；原人物、软件界面、原配乐、变声及生成式变脸未复制。每条适配差异在目录/审核页注明。机械通过、编码帧审查与用户审美通过分别记录。

[验证记录](../assets/social-grammars/validation.json)保存60个实际输出hash、尺寸/帧数、seek检查与编码帧查看范围。一次真实移动人物的`d11`整片接入已通过，人物返回、母片音轨、缓存和无效输入拒绝均检查；这不代表所有模块的动态人物组合都已验证。完整合成的浏览器检查保留一条原有字幕嵌套结构lint提示，实际布局、运动、运行与文字对比度检查通过。用户的审美确认仍待对话审核。
